# Git & collaboration rules — Sanju's agent

You are building **Sanju's part** of SweatboxAI (voice pipeline, parser, composer, TTS, browser audio, LLM and fal features). Three people and three AI agents work in one repo at the same time. These rules keep us from overwriting each other. Follow them exactly.

## 1. What you may edit
```
server/voice/
server/agents/
server/pilot/readback.py  validator.py  variants_build.py
web/src/audio/                          (plain TypeScript + Web Audio, NO React, NO layout)
server/tests/voice/                     (except golden_parse.jsonl, which Tudor writes; you only read it)
data/readback_variants.json  data/voices.json   (generated by your code)
```
**Everything else belongs to someone else.** Never edit it, even to "fix" a bug or make an import work.

| Owner | Their area |
|---|---|
| Tudor | `data/` (other files), `server/sim/`, `server/rules/`, `server/pilot/engine.py decision.py errors.py clearance.py`, `server/tests/sim|pilot|rules/`, `server/tests/voice/golden_parse.jsonl` |
| Bhavin | everything else: `server/main.py hub.py session.py feed.py`, `server/contracts.py`, `web/src/protocol.ts`, all of `web/` except `web/src/audio/`, `CLAUDE.md`, `README.md`, dependency files |

**If a change outside your area seems needed: STOP and tell Sanju.** He will ask the owner in the group chat. Write down exactly what you need (file, function, why).

## 2. One-time setup
```sh
git clone <repo-url> && cd sweatbox-ai
sh tools/git/install-hook.sh sanju      # blocks commits outside your area
cp .env.example .env                    # ANTHROPIC_API_KEY, ELEVENLABS_API_KEY, FAL_KEY
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
cd web && npm install && cd ..
```
Do not add Python or npm dependencies. They're all pre-installed by Bhavin. If something is genuinely missing, tell Sanju; Bhavin adds it.

## 3. Work loop (repeat for every task)
```sh
git checkout main && git pull --rebase origin main
git checkout -b sanju/<short-task>       # e.g. sanju/scribe-stream
# ...work, commit small and often...
git add <only your files> && git commit -m "[voice] Scribe realtime streaming + manual commit"
pytest server/tests/voice
git pull --rebase origin main
pytest && python server/tests/integration/smoke_test.py && (cd web && npm run build)
git checkout main && git merge --ff-only sanju/<short-task> && git push origin main
git branch -d sanju/<short-task>
```
- Merge to `main` at least every 1–2 hours. Never keep a big branch overnight.
- Commit prefixes: `[voice]`, `[parser]`, `[composer]`, `[tts]`, `[audio]`, `[agents]`, `[fal]`.
- Never `git push --force` to `main`. Never commit `.env`, API keys, recorded audio, or `runs/`.

## 4. Shared files — hands off
- **`server/contracts.py`** defines your interfaces (`VoiceAPI`, `ComposerAPI`, `NarrativeAPI`) and every message you send (`CaptionMsg`, `AudioStartMsg`…). Implement and send them **exactly**. Need a new field? Sanju asks Bhavin; only additive optional fields are allowed (CONTRACTS.md §7).
- **`web/src/protocol.ts`** defines the `AudioEngine` interface your `web/src/audio/index.ts` must implement. Bhavin's UI calls only those methods. Don't add UI code to your module, and don't import from `web/src/app|radar|viz|ui`.
- **`server/session.py`** wires your classes in. Constructor signatures are fixed: `VoicePipeline(world, pilot, composer, bus, hub)`, `Composer(data_dir)`, `Narrative()`.
- **`golden_parse.jsonl`** is Tudor's: read it in tests, never edit it. Wrong expectation? Tell Sanju.

## 5. If you hit a merge conflict
- Conflict in **your** files: resolve it, re-run the tests.
- Conflict in **anyone else's** file (shouldn't happen): don't hand-merge it. Take main's version (`git checkout --theirs <file>` during a rebase), finish the rebase, and tell Sanju.
- The hook blocks a commit: unstage the listed files (`git restore --staged <file>`), revert your edits to them, and report what you needed.

## 6. Done means
Tests pass (incl. golden-set accuracy), the smoke test passes, the web build passes, your branch is merged into `main`, and the voice round trip still works from the radar page.

## 7. Post-MVP technical-depth ownership
After the end-to-end MVP works, Sanju owns transmission-stage tracing and voice benchmarks, including `server/tests/voice/bench/`. Coordinate optional event/API shapes with Bhavin before changing contracts. Traces must be append-only, use monotonic durations, and fail open so instrumentation cannot interrupt voice processing. Report measured sample counts and conditions; do not present targets as results.
